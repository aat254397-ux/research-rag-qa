# 科研文献 RAG 问答助手 (Research Document QA)

面向科研论文阅读的本地文献问答应用：导入 PDF，用中文问题检索英文原文，再由大模型基于选中的片段组织答案，并展示出处、页码和原文。

首次在新环境运行，请先看 [启动与交付指南](docs/QUICKSTART.md)；已有环境与索引的用户不需要重新安装、下载模型或加载文献。以下各节保留分阶段的学习过程与技术说明。

当前功能：

1. 读取 TXT、Markdown 和普通文本型 PDF；
2. 按字符切片，PDF 按页处理并保留页码；
3. 建立 TF-IDF 索引并执行相似度检索；
4. 使用模拟客户端或 DeepSeek 生成回答；
5. 返回参考资料的原文、来源、位置及 PDF 页码；
6. 通过 FastAPI 提供资料加载与问答接口；
7. 保存索引到本地 JSON 快照，服务重启时自动恢复；
8. 单独检索资料，查看原文、页码、排名和分数，不调用生成模型；
9. 基于同一批切片分别建立 TF-IDF 和 E5 索引，支持中英文问题检索英文论文；
10. 使用 Cross-Encoder 对候选重排，检索接口和问答接口共用两阶段检索流程；
11. 提供本地网页工作台，可加载文献、提问、单独检索并展开参考原文。

独立学习示例：用户已安装并运行本地 E5，英文、中文问题均将直接介绍 MJO 输入变量的段落排在第一。

## HTTP 接口

安装依赖：

    python -m pip install -r requirements.txt

启动开发服务：

    python -m uvicorn api:api --reload --host 127.0.0.1 --port 8000

网页工作台：http://127.0.0.1:8000/

接口文档：http://127.0.0.1:8000/docs

- GET /：打开网页工作台。
- GET /health：检查服务能否响应。
- GET /index/status：查看当前资料、索引来源、快照路径及实际文件大小。
- POST /index/embedding/build：复用当前切片建立 E5 索引，单独保存，不重新解析 PDF。
- POST /documents/load：用给定本地资料路径建立新索引，保存成功后替换当前索引。
- POST /search：检索及可选重排，返回排名、分数和原文，不调用生成模型；模型推理在本机进行。
- POST /ask：提交问题，返回答案和实际检索到的参考资料。

`/search` 和 `/ask` 共用以下请求字段：

- question：必填，去除首尾空白后为 1～2000 个字符。
- top_k：默认 2，允许 1～10，表示最终返回或用于生成答案的片段数上限。
- retriever：默认 tfidf；填写 embedding 时使用已建立的本地 E5 索引。
- min_score：不填或为 null 时，tfidf 使用 0.1，embedding 使用 -1.0（首轮不过滤，先观察排名）。显式填写时，tfidf 允许 0～1，embedding 允许 -1～1。
- rerank：默认 false；为 true 时，对 E5 候选重新打分后再选取 top_k 段。本版开启时要求 retriever=embedding。
- candidate_k：默认 10，允许 1～50；仅在开启重排时使用，必须不小于 top_k。50 是当前 CPU 演示的候选数量限制，不是模型原理上的上限。

只有 `/ask` 使用 `mode`：默认 mock；填写 deepseek 时发送真实模型请求并产生相应费用。`/search` 不需要 `mode`。

DeepSeek 配置保存在本地 `.env`，字段为 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL` 和可选的 `DEEPSEEK_BASE_URL`。模型默认 `deepseek-flash`，地址默认 `https://api.deepseek.com`；使用阿里云百炼时，需要一起切换为百炼的密钥、对应地域的兼容接口地址和实际模型 ID，具体步骤见 [百炼配置](docs/QUICKSTART.md#使用阿里云百炼调用-deepseek)。`.env` 已加入忽略规则。

## 加载 PDF 文献

先启动服务，在 `/docs` 中调用 `POST /documents/load`：

```json
{
  "paths": ["D:/papers/example.pdf"]
}
```

`paths` 是运行服务的这台电脑上的文件路径。JSON 中建议使用正斜杠 `/`；填写 Windows 反斜杠时需要写成 `\\`。

加载接口读取资料、建立并保存索引，不调用模型。返回 `indexed_pdf_pages`（参与索引的 PDF 页数）、`chunk_count`（切片数）及 `index_storage`。资料全部成功处理并保存后才替换索引，失败时保留原索引。每次加载都会替换整个资料库，不是追加文献。

随后调用 `POST /ask`。例如：

```json
{
  "question": "Which variables are used to construct the MJO index? Answer in Chinese and cite the PDF page numbers.",
  "top_k": 3,
  "min_score": 0.05,
  "mode": "deepseek"
}
```

PDF 首版每片最多 1000 个字符，重叠 200 个字符；不跨页切分，切片编号在同一文件内连续。`page` 是从 1 开始的 PDF 文件顺序页码；`start`、`end` 是提取后该页文字中的字符位置，左闭右开，不是原始 PDF 的版面坐标。

默认检索仍是基于词面匹配的 TF-IDF，英文论文先使用英文关键词提问；建立 E5 索引后，可显式选择 embedding，观察中英文问题的检索结果。两类检索分数不是同一套标尺，上述 Top-K 和相似度阈值需要分别评测。

PDF 文件不会被上传或修改；只有问答时检索选中的文字片段随 Prompt 发往模型服务。

当前 PDF 提取不含 OCR，不保证双栏、表格、公式和图示的完整解析。短字符切片仍可能切断词或句子，按页切分也会分开跨页段落。

## 索引持久化

当前选择 JSON 快照：它适合现阶段的字典、列表结构，不增加依赖，而且可以直接查看内容。本阶段是本机、单服务进程、整体替换索引；尚未引入数据库、多进程一致性或增量更新。

- 首次启动没有快照时，仍使用两份示例文档建立内存索引。
- `POST /documents/load` 成功后，快照保存到项目内 `data/indexes/retrieval_index.json`。
- 快照包含切片原文、来源、页码、词表、IDF 权重和向量，而不只是文件路径。
- 后续重启或自动重载时直接读取快照，不重新解析 PDF、计算索引或调用模型。
- 原文献被修改后，快照不会自动更新，需再次调用加载接口。即使原文件被移动，旧快照仍可检索，但返回的来源路径可能已经失效。
- 文件带有格式版本与 `tfidf-v1` 算法标记；未来修改算法或结构时需要明确迁移或重建，不能混用旧索引。

保存时先写同目录临时文件，再替换正式快照；随后切换内存索引。这样可降低写入中途失败损坏旧快照的风险，不等于数据库事务或完整备份。当前只保留最新快照，不保留历史版本。快照损坏或版本不兼容时，服务会明确停止启动；先备份并移走该文件，再启动并重新加载资料，不会默默切回示例库。

通过 `GET /index/status` 查看：

- `index_origin`：`sample_documents` 是示例库，`loaded_documents` 是本次运行加载的资料，`disk` 是从快照恢复。
- `index_storage`：`memory` 表示仅内存，`memory+disk` 表示内存索引与磁盘快照并存。
- `snapshot_exists`：快照是否存在。
- `snapshot_size_bytes`：快照的实际字节数；除以 `1024 * 1024` 可换算为 MiB。

JSON 不是最紧凑的向量存储格式，TF-IDF 中的大量零值也会占空间。先用状态接口测量，再按规模考虑稀疏矩阵、SQLite 或 Embedding 向量库，不预先承诺固定存储量。

`data/indexes/` 已加入 Git 忽略规则，因为快照包含论文原文和本地路径；忽略规则不是加密，也不是备份。正式服务启动命令不变。`create_app(index_path=None)` 用于隔离普通接口测试，持久化测试则用临时目录中的真实文件，均不读取或覆盖正式论文索引。

本次新增验证覆盖保存/恢复前后检索一致、页码保留、格式不兼容、写入失败保留旧快照、服务重新创建后恢复，以及资料加载失败保留原库。全部自动化测试仍由用户执行：

    python -m unittest discover -s tests -v

手动验证：加载一次 PDF，查看状态；停止并重新启动服务，再查看状态。预期 `index_origin` 从 `loaded_documents` 变成 `disk`，资料和切片数量不变。该验证不需要调用付费模型。

## 单独查看检索结果

回答不理想时，需要先区分“没有选中正确原文”和“选中了原文但模型没有正确使用”。`POST /search` 复用 `/ask` 的实际检索函数，只返回参考资料，不生成答案、不使用真假模型客户端、不修改或保存索引。

刷新 `/docs`（当前版本 0.9.0），在 `/search` 提交：

```json
{
  "question": "Which variables are used to construct the MJO index? Answer in Chinese and cite the PDF page numbers.",
  "top_k": 3,
  "min_score": 0.05
}
```

此处保留上次的问题原文、Top-K 和阈值，是为了复现之前的检索条件，不表示它们是最优设置。`/search` 中问题里的回答格式要求也会作为检索文本处理；不会真的生成中文回答。

返回 `retriever`、`effective_min_score`、`match_count` 和 `references`；参考资料按分数从高到低排列，`rank` 从 1 开始。查看每条的 `page`、`chunk_id`、`text`，确认是否包含问题所需的信息。`score` 是所选向量表示下的余弦相似度，不是答案正确率。阈值过滤后没有结果时返回 `200` 和空列表；TF-IDF 问题完全不含已索引词汇时沿用原逻辑，返回 `400`。

如果原文已提取但不在选中的片段里，下一步检查检索文本、排名和参数；如果选中的片段足够回答，而最终答案仍然不对，再检查 Prompt 和生成阶段。不要把一次问题的改善当作整个资料库质量提升，后续需要用多组问题评测。

## 独立 Embedding 小例子

本例使用已训练好的 `intfloat/multilingual-e5-small`。Sentence Transformers 是负责加载和使用模型的 Python 库，E5 才是实际模型；安装库不等于已经下载了模型权重。这里只使用模型进行编码，不训练或微调。

选择本地多语言模型，是为了演示英文和中文问题对英文段落的检索，同时不增加一个付费 API。代价是需要先安装依赖、下载模型文件，并占用本机内存和计算资源。默认使用 CPU，避免先处理显卡配置；这不代表安装文件很小，依赖中包含 PyTorch 等软件。

在已激活项目虚拟环境的终端安装可选依赖：

    python -m pip install -r requirements-embedding.txt

随后运行：

    python embedding_demo.py

首次运行会尝试从 Hugging Face 下载模型，缓存位置由程序打印，位于项目的 `data/model_cache/`。该目录已加入 Git 忽略规则；它存的是模型文件，不是论文索引快照，也不是安装库的 `.venv`。已有缓存可以复用，但在线加载时仍可能检查远端文件。此步骤需要可用网络；若下载失败，先保留报错排查，不关闭 SSL 校验、不改 DeepSeek 地址、不使用未核实的镜像。

例子准备两个问题（同一含义的英文、中文版本）和三个英文段落：A 介绍指数的输入变量，B 泛泛介绍 MJO，C 介绍 Python 虚拟环境。E5 将两组文本分别转换成向量，再复用项目已有的 `cosine_similarity()` 计算排名。模型只负责产生向量，原有余弦相似度计算方法没有改变。

关键参数与约定：

- `query: ` / `passage: `：E5 训练时区分问题和候选段落的前缀，中文问题也使用它们，不是翻译指令。
- `device="cpu"`：在本机 CPU 上计算。
- `cache_folder`：保存下载的模型文件的硬盘目录。
- `normalize_embeddings=True`：将每个向量的长度归一化为 1，不表示正确率提高；后续仍使用余弦相似度比较方向。
- `show_progress_bar=False`：只关闭这两次编码的进度条，不代表不执行计算。

预期向量形状分别为 `(2, 384)` 与 `(3, 384)`：有两个问题、三个段落，每段文本对应 384 个数字。输出的前 8 个数字来自真实模型，仅用于观察向量的样子；每一维不直接对应某个词，也没有预先指定的人类语义标签。

程序展示全部三个段落的分数和排名，不硬编码“正确段落排第一”，也不照搬旧的 `min_score=0.05`。尤其 E5 分数的绝对大小不能当作正确率；先观察同一问题下的相对排名，之后再用多组真实论文问题评测。

该例不会加载本地论文、读取密钥、调用 DeepSeek、写入或替换现有索引，也不会自动随 API 启动。已有的 79 个 TF-IDF 切片继续保持原状。示例的安装、模型下载与运行已由用户完成，未代跑测试或模型推理。

参考：[E5 模型说明](https://huggingface.co/intfloat/multilingual-e5-small)、[Sentence Transformers 安装说明](https://sbert.net/docs/installation.html)。

## E5 接入真实论文检索

这一版仍使用同一批原文切片，不同时改变 PDF 解析和切片策略。TF-IDF 快照保留原名，E5 快照单独存放在同目录的 `retrieval_index.e5.json` 中；都在已有的 Git 忽略目录内。原文、页码、切片编号和字符位置保持不变，E5 输入保留原始文字，未额外做连字或断词清理。

用户已经下载模型，服务端因此固定使用本地缓存中的权重版本 `614241f622f53c4eeff9890bdc4f31cfecc418b3`，不自动联网补下载。启动时不加载 PyTorch 和模型；首次构建或首次语义查询时按需加载，随后在同一进程复用。E5 向量快照包含模型名、权重版本、池化、归一化、前缀、最大长度等编码配置，避免用不同配置的模型查询旧向量。

建索引时用 `passage: ` 编码所有片段；提问时只用 `query: ` 编码当前问题。CPU 编码的初始 batch_size 为 8，是控制内存占用的保守设置，不代表已经做过吞吐调优。编码前检查包含前缀、特殊 token 在内的实际长度；超过 512 时明确报出位置，不静默截断。当前不改变原始切片数，因此若遇到该错误，需要缩短问题，或调整切片并重新建立两类索引后再比较。

先在 `/index/status` 确认仍是目标论文及 79 个切片。然后展开 `POST /index/embedding/build`，点击 Try it out → Execute，无需填写正文。该请求会在本机执行真实 E5 编码并保存快照，不调用 DeepSeek。成功时应返回 `status: ready`、`dimension: 384`、`chunk_count: 79`。如果当前加载的是示例库，它也只会为示例库建索引，不会自动寻找其他论文。

随后在 `/search` 提交：

```json
{
  "question": "Which variables are used to construct the MJO index?",
  "retriever": "embedding",
  "top_k": 3
}
```

此处没有填写 min_score，实际使用 -1.0，让第一轮观察不受过滤阈值干扰。把 retriever 改为 tfidf 就可回到原方法；不填 retriever 仍默认 tfidf。也可以保持 embedding，将问题改成中文，检查跨语言检索。先观察是否找回含三个变量的片段，不把单题成功当作整个系统的质量结论。

`/ask` 同样支持 retriever。mode 与 retriever 独立：retriever 决定如何检索，mode 决定生成时使用模拟客户端还是真实 DeepSeek。尚未校准语义阈值时，系统可能为库外问题也返回相近片段，不能仅靠相似度保证可回答或引用正确。

E5 快照还保存当前切片和元数据的内容签名。加载不同资料后，旧快照会标为 stale，选择 embedding 返回 409，要求为新资料重建；不会悄悄用旧资料，也不会偷偷退回 TF-IDF。构建期间若资料变化，构建结果不会保存或切换。写入失败保留旧版。服务重启会自动恢复匹配的 E5 向量快照，不重新编码全文；首个语义查询仍需把 E5 权重加载到内存，以编码新问题。

在 `/index/status` 的 embedding 字段查看状态：not_built 尚未构建，ready 可用，stale 资料已变化，invalid 快照损坏或配置不兼容。origin 的 built 表示本次构建，disk 表示从磁盘恢复；model_loaded 仅表示本进程是否已加载模型权重，不是索引是否存在。

用户已确认 E5 接入后的全部 70 项测试通过，其中新增测试覆盖有符号向量排序、元数据及快照协议、编码配置不兼容、资料变化后的过期保护，不加载真实或虚假的 E5 模型，也不验证模型语义效果。真实模型效果由前述手动检索对照单独验证。全量回归仍由用户执行：

    python -m unittest discover -s tests -v

## 独立重排小例子

中文问题的前 10 个 E5 候选中，第 7 名（第 1 页切片 1）包含完整答案，而前 4 名不包含。用户已运行真实重排模型，切片 1 从原第 7 名升至新第 3 名，最终前三段中包含完整依据。

对比方案：直接增大送给生成模型的片段数，改动最少，但会增加上下文和无关材料；Cross-Encoder 对候选重新打分，需要额外模型和逐对计算，但有机会在少量最终片段中保留完整依据。本轮先保持问题、候选、原文完全不变，只观察重排的影响，不同时修改 PDF 清洗和切片。

本例选择 `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`，它使用含中英文的 mMARCO 训练数据，能由已经安装的 Sentence Transformers 直接加载，不额外安装 FlagEmbedding。主要 safetensors 权重约 471 MB，另有分词器、配置等文件；这不是运行内存上限，也不需要下载仓库中的全部 ONNX、OpenVINO 或重复权重。选择它是为了复用依赖、控制下载规模，并展示重排的实际作用。

已将用户实际提交的中文 `/search` 前 10 名完整保存为项目内 `data/rerank_examples/mjo_zh_top10.json`。这是一次检索结果的固定副本，不是索引，也不是重新生成的候选；正文、原排名、分数、来源、页码保持不变。该目录已加入忽略规则，因为包含论文原文和本地路径；它仍需保留在本机才能运行默认示例，不会随仓库分发，也不在 README 中复制全文。

在项目虚拟环境已激活的终端中运行，无需打开 `/docs` 或启动服务：

    python rerank_demo.py

若原终端正在运行 Uvicorn，可以先按 Ctrl+C 停止服务并释放其模型内存，或者使用另一个已激活相同虚拟环境的终端。停止服务不会删除已经保存的索引。现有 `requirements-embedding.txt` 中的依赖足够，不需要再安装新库。

首次运行会联网下载新重排模型，缓存仍放在 `data/model_cache/`，权重版本固定为 `1427fd652930e4ba29e8149678df786c240d8825`，只加载 safetensors，不启用远端自定义代码。后续若希望完全使用本地缓存、不联网检查：

    python rerank_demo.py --local-files-only

脚本首先展示 E5 原排名，然后展示全部重排后的名次、原名次、切片号、页码、E5 分数和重排分数，最后打印前 3 个片段的完整原文，供人工检查是否真的回答问题。没有硬编码正确切片或期望名次；没有用答案关键词来抬高分数；也没有删除不利候选。

几个参数的职责：

- 候选数为输入文件中真实保存的数量，本例是 10；脚本不重新检索，也不为了补满数量增加材料。
- `--top-k 3`：默认展示重排后前 3 段的全文，不减少被打分的 10 个候选，也不改变 `/ask` 参数或发送给 DeepSeek。
- `--batch-size 4`：每批处理 4 对“问题、片段”，是 CPU 演示的保守起点，不是只比较 4 个候选；内存紧张时可改成 1。
- 问题与片段合计最多 512 个 token，包含特殊分隔 token；不是两边各 512，也不是 512 个字符。超长明确报错，不静默截断。
- `Identity()`：不改变模型输出的原始分数。这些分数可能为负或大于 1，不是余弦相似度、正确率，也不与 E5 分数直接比较数值大小。
- 此模型直接接收 `(question, passage)` 文本对，不沿用 E5 的 `query: ` / `passage: ` 前缀。名称中的 H384 是内部隐藏层维度，本例每个文本对只输出一个相关性分数，不输出 384 维句向量。

也可用 `--input "文件路径"` 读取另一次完整保存的 embedding 模式 `/search` JSON 结果；默认不修改输入文件，不保存排名报告，不读取原始 PDF、索引或密钥，不调用 E5、FastAPI 或 DeepSeek，不训练模型。模型加载和长度检查/重排的耗时分别打印，避免把首次下载时间当成查询延迟。

独立示例已由用户运行成功；模型已缓存。现在演示脚本与正式接口复用 `reranking.py`，无需重新下载。脚本保留允许下载的选项，正式接口只读取本地缓存。

参考：[模型说明](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1)、[模型文件及体积](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1/tree/1427fd652930e4ba29e8149678df786c240d8825)、[mMARCO 数据语言](https://huggingface.co/datasets/unicamp-dl/mmarco)、[CrossEncoder 用法](https://sbert.net/docs/cross_encoder/usage/usage.html)。

## 在接口中使用两阶段检索

这一部分把已跑通的重排例子接入实际问答。检索与重排写在 `app.py` 的公共函数里，`/search` 和 `/ask` 调用同一套逻辑；接口只负责接收参数、选择组件和返回结果，避免纯检索看到一组片段、生成答案却用了另一组。

开启重排后，E5 先按 candidate_k 选取候选，Cross-Encoder 对全部候选逐对打分，最后保留 top_k 段。min_score 仍用于重排之前的 E5 过滤，不是重排分数阈值。候选不足时不会强行补满；返回的 candidate_k 是设置的数量上限，不是实际命中计数。关闭重排时，仍直接按 top_k 选取，旧请求不需要修改。

服务启动时仅创建轻量组件，不立即加载两个模型。第一次使用时分别加载本地 E5 和重排权重，同一进程的后续请求复用；无需重新解析 PDF 或重建索引。重排模型没有文献索引，它对当前问题和当前候选直接打分，因此新增资料后也不需要为它另建索引。

在项目虚拟环境中启动服务：

    python -m uvicorn api:api --reload --host 127.0.0.1 --port 8000

刷新 http://127.0.0.1:8000/docs，确认版本为 0.9.0。在 `/ask` 中直接运行：

```json
{
  "question": "构建 MJO 指数使用了哪些变量？",
  "retriever": "embedding",
  "rerank": true,
  "candidate_k": 10,
  "top_k": 3,
  "mode": "deepseek"
}
```

该请求完成中文问题编码、E5 候选检索、Cross-Encoder 重排、Prompt 构建和真实 DeepSeek 回答。只有最后一步调用付费生成接口。无需先加载论文或重新构建 E5，当前持久化索引会在启动时恢复。相同参数去掉 mode 后可用于 `/search`，只查看最终片段，不生成答案。

开启重排时，每条 references 保留：

| 字段 | 含义 |
| --- | --- |
| rank | 最终选取中的名次 |
| retrieval_rank | E5 候选集合中的原始名次 |
| score | 原始 E5 余弦相似度 |
| rerank_score | Cross-Encoder 原始打分 |
| page / chunk_id | 实际来源页码及切片编号，不随排序改变 |

`GET /index/status` 新增 reranker 字段，可查看模型名、固定权重版本和 model_loaded。model_loaded=false 表示当前进程还未加载模型，不是文献索引丢失。模型缓存缺失返回 503，参数不符合要求返回 422；都不会覆盖已有索引。

新增基础测试只检查分数排序与元数据保留、空候选无需加载模型，以及候选数量和最终数量的参数约束，不增加真假模型客户端练习。若要执行回归，仍由用户运行统一命令：

    python -m unittest discover -s tests -v

## 本地网页工作台

启动命令不变，在浏览器打开 http://127.0.0.1:8000/ 即可；原来的 /docs 保留调试。网页与 API 在同一地址下运行，JavaScript 直接请求 /ask、/search 等现有接口，不需要另起前端服务器、安装 npm 依赖或配置跨域。只提供 web/dist 中的静态文件，不把项目根目录、密钥或文献快照作为静态目录开放。

三个文件各有职责：index.html 提供界面结构，styles.css 提供布局与样式，app.js 处理点击事件、构造 JSON 请求及显示响应。前端不实现切片、检索、重排和生成，也不保存 API 密钥；这些仍由原有 Python 后端负责。

相关原理可对照 [FastAPI 静态文件](https://fastapi.tiangolo.com/tutorial/static-files/) 与 [浏览器 fetch 请求](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)：前者提供页面资源，后者让页面调用现有 HTTP 接口。

页面打开后只读取文献库状态，不自动建索引、不自动发送问答。已有论文与 E5 快照就绪时，直接输入问题并点击“生成答案”；默认使用 E5 + 重排、10 个候选和 3 个最终片段。示例问题按钮只填入问题，不自动提交。也可点击“只检索”，不调用 DeepSeek。

文献库区域显示实际文件、PDF 页数、切片数和持久化状态。“加载 / 更换文献”填写本机文件完整路径，一行一个，支持直接粘贴 Windows 路径，无需手动写 JSON 或转义反斜杠。加载仍会替换当前资料库。若 E5 索引待建、过期或失效，可点击“建立 E5 语义索引”；已就绪时按钮禁用，避免误操作。修改文献后旧答案清空，防止误把上一份资料的回答当作当前结果。

答案区域显示实际模型返回内容，保留换行并支持 **加粗**；其余 Markdown 按普通文字显示。参考片段可展开查看原文、文件路径、页码、新旧排名及两种分数。页面使用文本节点显示模型和文献内容，不直接把返回内容作为 HTML 执行；不依赖外部字体、图片或 CDN。

手动演示只需：启动服务 → 打开首页 → 点击示例问题 → 点击“生成答案” → 展开第 1 页参考片段。首次问答加载模型可能较慢；页面展示的是整次请求总耗时，包含模型加载、检索、重排和生成，不冒充单独的推理耗时。页面没有聊天记忆，刷新会清空当前回答，但不会删除后端保存的索引。
